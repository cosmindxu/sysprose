How this was computed. Rows come from scripts/todo-dashboard/coverage-universe-source.json, the normative clause inventory: KerML 8.3 metaclasses, SysML v2 Part 1 §7 textual construct clauses, §8.2.3 / §9.2.20 standard view definitions, and the Systems Modeling API and Services §7.2 / §8.1.3 service clauses; the class register (docs/CONSTRAINT-CLASSES.md) supplies the CON rows. Each clause-bearing row cites its clause id and number in the Clause column; the CON rows name the class register, and an unclaused row says so. The row ids are the aliases the matrix has always used, so re-keying the universe to the clauses did not move a row's state. A row with no clause in the adopted documents (the Other API group's POST /transform and /validate; no rendering clause for the Browser, Grid and Geometry views) says so and is never given an invented clause. A TXT row is read where a pinned probe (scripts/todo-dashboard/probes/, run by probes/run.ts over the four decision surfaces) reaches a row and quotes its sentence — the corpus usage count and corpus.test.ts's parse evidence are kept beside it, not substituted for it; a construct that files no row or only a structural read is partial, and a partial row is measured but is not in the construct-coverage numerator, so a row that was only parsed before drops out of it. A CON row is decided when its class level is differential-tested or tested, partial when experimental, refused when fenced/unpinned; a GRAPH row is rendered where an E2E spec asserts the view kind's panel (test/e2e/); an API row is decided where a conformance test asserts the group's endpoints (test/conformance/, CONFORMANCE §3–4). Weights are named per row. The Weight column carries the weight the weighted variant counts and its source: a TXT row is weighted by corpus usage (the models of the 637-model corpus that use the construct; a construct no corpus model uses keeps a floor of 1, so a measured row never vanishes from the denominator); a CON row is weighted by the class register's Rows column (counted rows — a worklist row of the corpus; no per-class generator model count is recorded in this repository, so the corpus row count stands in for it); an API or GRAPH row has no such count, so it counts 1. Both headers report two variants so no single percentage hides the choice: weighted uses each row's named weight, and equal counts every measured row once. A soundness count beside an area's row count joins two inputs and never enters a percentage. The dashboard's FALSE tier (scripts/todo-dashboard/ds_open.json) is open wrong-statement findings, each counted once in every area whose coverage row id or CON class name it names; one that names no row is reported as unattributed. A finding naming rows in more than one area is therefore counted in each of their headers but once in the card total, so the headers can sum above it. The class register's Table rows against is the differential-table rows a class has against its hand-computed answer, and its column is per class cell: the census charges one row against to every class the row rests on, so a row resting on three classes is three entries. The register half is therefore an entry count, not a count of distinct findings. The register's own open wrong-statement defects (docs/constraint-class-defects.json, kind wrong-statement) are a third input, counted once in the area of the classes they cap (1 today: D-x-pow-neg). The dashboard's FALSE tier is empty today; the register's entries are `lra` 2, `partial-context` 2, `per-instance` 2. Soundness is shown beside coverage and never folded into a percentage. KERML rows stay unmeasured here: no test pins the metaclass itself, and an API group whose endpoints this build does not ship stays unmeasured too (the Other group: POST /transform and /validate). The app's 17 views include the 11 standard view rows here; the four annotation primitives the earlier 02 §2.2 extraction dropped now have rows of their own. Pinned probes fill the remaining unmeasured rows as they land.
