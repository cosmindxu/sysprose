How this was computed. Rows come from 02-omg-standard-reference (§2.2 metaclasses, §3.2 textual areas, §4.1 view kinds, §5.7 API groups) and the class register (docs/CONSTRAINT-CLASSES.md). A TXT row is read where a pinned probe (scripts/todo-dashboard/probes/, run by probes/run.ts over the four decision surfaces) reaches a row and quotes its sentence — the corpus usage count and corpus.test.ts's parse evidence are kept beside it, not substituted for it; a construct that files no row or only a structural read is partial, and a partial row is measured but is not in the construct-coverage numerator, so a row that was only parsed before drops out of it. A CON row is decided when its class level is differential-tested or tested, partial when experimental, refused when fenced/unpinned; a GRAPH row is rendered where an E2E spec asserts the view kind's panel (test/e2e/); an API row is decided where a conformance test asserts the group's endpoints (test/conformance/, CONFORMANCE §3–4). Weights are corpus usage (TXT) or counted rows (CON). KERML rows stay unmeasured here: no test pins the metaclass itself, and an API group whose endpoints this build does not ship stays unmeasured too (§5.7's Other: POST /transform and /validate). The app's 17 views include the 11 §4.1 view kinds. Pinned probes fill the remaining unmeasured rows as they land.
